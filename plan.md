# Madar — mobile company operations

## Approach
Madar is an Expo Router / React Native / TypeScript app (Android, iOS and a responsive web build) backed directly by Supabase. There is no custom application server: PostgreSQL row-level security, guard triggers and SECURITY DEFINER RPCs enforce every rule, so the web, mobile and any direct API client share the same guarantees. The web build is a static SPA deployed on Vercel from the `main` branch of `alf-2006/madarhq`.

Implemented outcomes: (1) email/password auth via Supabase Auth, first-run workspace setup that creates the single system administrator, five-role authorization (admin, manager, supervisor, employee, viewer), employee management (create accounts, pre-authorized signup invitations, join requests with approval, password resets); (2) tasks with multiple assignees, reviewer, priority, dates and estimates; interactive table, kanban, calendar and timeline views; subtasks, comments, private attachments; a server-side work timer (one running session per employee) and manual time entries; submit-for-review, approve and return-with-note workflow; (3) role-scoped dashboards, projects and departments with progress and workload, a notification centre fed by database triggers, and an activity log; (4) reports of actual worked hours (from sessions, never task age), on-time completion, per member/project breakdowns, CSV export and CSV task import.

Authentication: Supabase email/password. The first visitor to an empty workspace creates the administrator through the `admin-users` Edge Function (`setup`), which refuses once an admin exists. Others either receive an account from an admin/manager (`create_member`), register with a pre-authorized email (auto-activated with the invited role and department), or submit a join request that stays `pending` until an administrator approves it. Pending and disabled profiles cannot read any company data. Timestamps are stored in UTC and displayed in the company timezone from `company_settings`.

Scope rules (enforced in SQL, mirrored in `lib/madar/permissions.ts` only to hide unavailable actions): administrators manage everything; managers manage their department's members, projects and tasks; supervisors manage department tasks; employees see and work on tasks assigned to them or created by them; viewers have read-only access. Only administrators change roles, departments or account status, and the last active administrator cannot be removed. Attachments live in a private Storage bucket and are served through short-lived signed URLs after a task-visibility check.

Not included: email delivery (invitations are in-app pre-authorizations, not sent emails), Google sign-in, push notifications and native store builds; these need external configuration.

## Project structure
- `app/`: Expo Router screens. `login.tsx` (sign in, join request, first-run setup); `(app)/` protected area: dashboard, tasks (+ `[id]` detail), projects (+ `[id]`), team (+ `[id]` member), departments, reports, notifications, settings, more.
- `components/madar/`: design system (`ui.tsx`), app shell (side rail on desktop, bottom dock on mobile), logo, task form/views, project and member forms, activity feed.
- `lib/madar/`: types, Arabic labels, timezone-aware formatting, permission mirrors, React Query data layer, session provider, CSV helpers.
- `lib/supabase.ts`: Supabase client (publishable key only).
- `supabase/migrations/`: schema, business logic triggers/RPCs, RLS policies and function grants (all applied to project `nuotqfpkoffuwkoqdtte`).
- `supabase/functions/admin-users/`: Edge Function for privileged account operations using the service role.
- `assets/images/`: launcher, adaptive, splash and favicon images generated by `scripts/generate-icons.py`.

## Visual direction
Three considered tails: Swiss editorial operations, probability 0.06; warm architectural workspace, probability 0.04; technical monochrome ledger, probability 0.03. Selected: warm architectural workspace.

**Design Movement:** Contemporary editorial product design, borrowing precise wayfinding from architectural studio tools.
**Core Principles:** Arabic-first clarity; one-handed actions; visual restraint; honest and traceable information.
**Color Philosophy:** Warm ivory surfaces and deep forest ink convey calm control; emerald identifies progress and the primary action, amber signals attention, soft red communicates delays without alarm overload.
**Layout Paradigm:** Right-side compact desktop rail with a spacious asymmetric workspace; portrait mobile header, stacked editorial panels and a five-destination bottom dock, with secondary destinations under More.
**Signature Elements:** Open orbital logo, forest welcome panel with subtle orbit outlines, tiny spaced section labels and muted color-coded status pills.
**Interaction Philosophy:** Tap a card to inspect; contextual actions are nearby; creation uses a focused sheet; filters and views retain context; errors never silently discard input.
**Animation:** 160–220ms fade/slide for sheets and navigation, short button press feedback, no continuous decorative animation, reduced motion honored where feasible.
**Typography System:** Bundled Cairo Arabic family for clean Arabic body and semibold headings, system sans for compact Latin numbers; 28–32px primary titles, 18–20px section titles, 13–15px body and 11–12px metadata.
**Brand Essence:** مدار keeps a company's people, tasks and actual work in one clear orbit. Calm, precise, capable.
**Brand Voice:** Brief operational Arabic, not machine-translated slogans. Examples: “كل التفاصيل، في مدار واحد.” and “أرسل للمراجعة”.
**Wordmark & Logo:** Arabic مدار wordmark with an open orbital ring and a square progress marker, repeated as the launcher icon without baked rounded corners.
**Signature Brand Color:** Deep emerald #176B52.
